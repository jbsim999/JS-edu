# 최종 화면 검수

2026-10-19, 제품 UI 기준 소스 `415d7371438190e340f24bb94ae362f80366972d`. 기존 사용자 4179 탭과 저장 데이터를 보존하고 별도 4188 서버·Chrome 검수 탭에서 확인했다. 이 검수 중 제품 화면 소스 변경은 없다.

- 320×740: 클로저 실제 제출 7/7, 코드 편집·결과·버튼의 수평 넘침 없음. 검색형 사전에서 클로저 상세창 진입, 상세 Escape 후 검색 복귀, 검색 닫기 후 원래 사전 버튼 초점 복원. 상세창 자체 수평 넘침 없음, 코드 영역은 자체 수평 스크롤을 제공한다.
- 768×800: 라이트 화면의 본문·목차·학습 단계 합성 검토. 한글·이모지 메모와 테마를 저장하고 재로드 복원 확인. 이는 OS IME 조합 입력 검사가 아니다.
- 640×360: 다크 화면의 목차 팝업과 내부 스크롤·현재 위치 강조·닫기 버튼 및 초점 복원 확인.
- 1440×900: 다크 화면의 본문·사전·현재 위치 반사광/그림자·핵심 노란 버튼의 합성 검토.

실제 캡처와 DOM 측정은 `artifacts/final-screen/`에 보존한다. 최종 승인 캡처는 `320-glossary-dark.png`, `768-light.png`, `640x360-toc-dark.png`, `1440-dark.png`다. 앞선 `640x360-toc-light.png`는 팝업 렌더 직전 화면이므로 팝업 근거로 사용하지 않는다. 이 기록은 브라우저 viewport 에뮬레이션이며 실제 모바일 기기 검사가 아니다.

위 범위 판정은 **PASS**다. Chrome 도구의 확대 키 입력은 실제 배율을 바꾸지 않아 200% 통과로 기록하지 않았다.

추가로 실제 Electron 44.9.0의 `webContents.setZoomFactor(2)`에서 배율 2, DPR 1→2, viewport 1424×895→712×447을 확인했다. 총괄이 `artifacts/desktop-smoke-06/`의 dark/light 200%·용어집 화면과 `artifacts/desktop-smoke-07/`의 Node 100/200% 제출·재시작 복원 합성 화면을 직접 검토했다. 페이지 수평 넘침·버튼 겹침·읽기 불가 잘림 없이 정상이며 이 화면 범위는 **PASS**다. 해당 중간 후보의 전체 native 검사는 하네스의 boot/cancel/함수 반환 직렬화 전제 오류로 FAIL이었다. 화면·채점 부분 PASS를 전체 native 완료로 확대하지 않는다. 최종 ZIP의 native 결과는 패키지 최종 검증에서 별도 연결한다.

물리 모바일 기기·OS IME 조합·스크린리더는 사용 가능한 검사 환경이 없어 미검증이다. 자동 테스트의 dialog 응답 스텁도 실제 OS 대화상자 키보드 조작 검사와 구분한다.

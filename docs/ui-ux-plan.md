# JavaScript-edu 학습 화면·용어집 기획

2026-10-15 승인 반영: 사용자가 피스타치오 프리미엄 효과와 다크 모드에 만족하고 실제 개발을 승인했다. 현재 시각 기준은 아래 2절의 초기 인쇄물 방향보다 이 문단을 우선한다. 밝은 피스타치오 바탕/크림 본문과 짙은 숲색 다크 모드, 노란 핵심 버튼, 얇은 가장자리 반사광, 접지·주변 이중 그림자, 반투명 사전 면을 채택한다. 활성 목차에도 같은 재질을 약하게 적용하고 2px 위치 표시선을 유지한다. 효과를 끄면 반사광·그림자·blur를 제거하고 불투명 면을 사용한다. 본문 텍스트 자체의 opacity는 낮추지 않으며 reduced-motion과 backdrop-filter 미지원 대체를 제공한다.

제품 구현 위치는 web/이며 `npm run dev`로 연다. 실제 교재 초안 1개와 6개 개념 미리보기, 5단계 전환, 용어집 검색·상세 모달, 개정별 함수 본문 초안·메모 저장을 연결한다. 다크/효과 설정은 학습 초안과 별도 저장한다. 코드 실행·자동 채점·성취 집계·완성 IDE는 아직 없다. prototypes/learning-workspace와 대화 내 스타일 후보는 이전 검토 자료로 보존한다. 아래 최초 범위·시각 토큰은 기획 이력이며 현재 제품 전체의 구현/검증 증거가 아니다. 실제 검사 범위는 verification.md를 따른다.

기준일: 2026-10-14. 승인 범위: UI/UX 기획과 작동하는 화면 시안. 이 문서는 제품 화면·IDE·실행기 구현 완료를 뜻하지 않는다. 강의 구성과 번호는 [로드맵](roadmap.md), 교육·실행 상태는 [제품 기획](plan.md)을 따른다. 시안은 [학습 화면](../prototypes/learning-workspace/index.html)과 [사용 안내](../prototypes/learning-workspace/README.md)에 분리하며, 실제 구현 범위와 검증 결과는 해당 안내와 [검증 기록](verification.md)에서 확인한다.

## 1. 설계 목표와 사용자 과업

대상은 다른 언어 경험자와 현직 개발자다. 사용자는 처음부터 강의를 읽거나, 실무에서 헷갈린 개념을 찾아 특정 절로 진입한다. 내용을 이해하는 동안 낯선 용어를 확인하고, 읽던 위치로 돌아오는 흐름을 가장 먼저 지원한다.

| 과업 | 기본 흐름 | 완료 조건 |
| --- | --- | --- |
| 원하는 개념 찾기 | 목차 → 강의 → 세부 절 | 현재 단원·강의·학습 단계와 선수 개념이 구분된다. |
| 개념 이해하기 | 설명 → 짧은 코드 → 상태 추적 → 확인 문제 | 핵심 설명을 펼침 동작이나 연속 팝업 뒤에 숨기지 않는다. |
| 용어 확인하기 | 사이드 검색 → 간단 설명 → 자세히 보기 → 본문 복귀 | 검색어·본문 위치·기존 입력을 잃지 않는다. |
| 공부 이어가기 | 최근 수업/단계 재개 → 기록 확인 | 방문·읽기 위치와 퀴즈/코딩 성취를 혼동하지 않는다. |
| 코드 검증하기 | 과제 → 편집 → 실행/제출 → 결과 해석 | 제품 구현 후 실제 실행 환경·현재 제출과 연결된 결과만 표시한다. |

시안의 핵심 검토 질문은 “본문이 충분히 넓고 읽기 편한가?”, “용어 확인 후 학습 맥락을 유지하는가?”, “학습 상태를 실제보다 앞서 보이게 하지 않는가?”다. 사용자 조사로 정량 검증된 선호나 학습 효과는 아직 없다.

## 2. 추천 시각 방향: 기술서의 본문과 여백 주석

추천안은 하나다. 기술서처럼 장번호와 제목, 본문, 여백의 참고 도구를 명확히 나눈다. 화면을 꾸미는 소개 영역보다 첫 설명과 코드가 먼저 보이게 한다. 따뜻한 중성 바탕에 짙은 먹색, 적갈색 강조 하나를 사용한다. 본문은 열린 면에 두고, 선과 여백으로 구획한다.

Java 화면이 “AI를 사용해서 만든 느낌”이라는 말은 사용자의 평가다. 특정 색이나 카드가 그 원인이라고 확정할 근거는 없다. 이번 비교는 제공된 Java 프로젝트의 `dist/styles.css`와 `dist/index.html`을 읽은 결과이며, 실제 렌더를 비교 검수했다는 뜻이 아니다.

| Java 소스에서 확인한 기준 | JavaScript-edu의 선택과 이유 |
| --- | --- |
| `styles.css`의 `--green`, `--green-soft`, `--paper` 중심 색상 체계 | 먹색·중성 면·적갈색의 인쇄물 조합으로 방향을 구분한다. |
| `--radius:16px`, `.lesson-card`, `.meta-chip`, 둥근 목차 활성 상태 | 본문을 큰 카드로 둘러싸지 않는다. 선택된 목차는 가는 세로선과 굵기로 표시한다. |
| `.workspace-grid`는 이미 목차+본문 2열이고 소개·목표 정보에 compact 개선이 있다. | 기존 개선을 보존할 기준으로 삼는다. JS의 3열은 충분히 넓은 화면에만 적용한다. |
| `.journey-card::before`의 장식 원 CSS가 존재하나 현재 HTML에서 그 카드 사용은 확인되지 않는다. | 장식 원이 현재 화면에 보인다고 단정하지 않는다. 새 안에는 학습 의미가 없는 장식 패턴을 넣지 않는다. |
| 목차, 5단계 탭, 출처, 실행/퀴즈 구분이 존재한다. | 좋은 정보 구조는 유지하고 화면 밀도·배치·타이포그래피를 새로 정한다. |

커다란 환영 문구, 카드마다 다른 배경색, 기능과 무관한 아이콘, 반복 통계, 연속 pill 배지, 그라데이션·유리 효과·떠 있는 장식은 쓰지 않는다. 강조는 현재 위치, 중요한 차이, 사용자의 다음 행동에 한정한다. 이 선택은 미적 유행의 일반 판정이 아니라 이 제품의 편집 방향이다.

### 시각 토큰

| 요소 | 제안값 | 사용 규칙 |
| --- | --- | --- |
| 바깥 바탕 | `#F7F6F2` | 전체 화면의 따뜻한 중성색 |
| 본문/팝업 면 | `#FCFCFA` | 큰 그림자 없이 필요한 영역만 구분 |
| 본문 | `#252824` | 제목·본문·주요 정보 |
| 보조문 | `#636861` | 절 안내·출처·영문 병기, 극도로 연한 글씨 금지 |
| 강조 | `#8A3E2F` | 현재 위치·본문 용어 링크·주요 행동 |
| 구분선 | `#D9D9D2` | 장식용 구분선. 입력 경계·포커스 식별을 이 색 하나에 의존하지 않음 |
| 포커스 | `#245CB0`, 2~3px 외곽선 | 배경과 구분되도록 offset 2~3px 확보 |
| 코드 면 | `#F0F1EC` | 흰 본문과 약한 차이, 코드 의미는 텍스트로도 설명 |
| 모서리 | 본문 0, 입력/버튼 3~4px, 팝업 6px | 일관된 작은 반경 |
| 여백 | 4·8·12·16·24·32·48px | 같은 역할의 항목은 같은 간격 사용 |
| 전환 | 100~150ms 색/불투명도 | 읽기 위치 이동 애니메이션 없음. reduced motion에서는 즉시 전환 |

제안 색의 계산 대비는 바탕 기준 본문 약 13.80:1, 보조문 5.27:1, 강조 6.91:1, 포커스 6.01:1이다. 흰 글자와 강조 버튼 배경은 약 7.47:1이다. 이는 지정 색의 수학적 계산이며 실제 화면 전체의 접근성 통과를 뜻하지 않는다. 일반 글자 최소 4.5:1은 [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 따른다.

### 타이포그래피

- 강의 제목: 명조 계열, `Noto Serif KR` → `Nanum Myeongjo` → `Batang` → serif. 데스크톱 30~34px, 모바일 26~28px, 줄높이 1.45. 설치된 글꼴로 먼저 렌더하며 외부 글꼴 로딩을 전제로 하지 않는다.
- 본문: `Pretendard` → `Apple SD Gothic Neo` → `Malgun Gothic` → system sans. 17px/1.8 기본, 좁은 화면에서도 최소 16px. 문장과 문단 사이 여백으로 읽기 리듬을 만든다.
- 내비게이션·사전 설명: 14~15px/1.6~1.75. 보조 정보도 12px 아래로 줄이지 않는다. 버튼은 내용이 늘면 높이가 자라야 한다.
- 코드: `Cascadia Code` → `SFMono-Regular` → Consolas → monospace. 14~15px/1.65. 줄번호는 선택·복사 결과에 섞이지 않는다.
- 본문 읽기 폭: 기본 620~720px, 실제 본문 열 최소 목표 520px. 공간이 모자라면 보조 열을 접는다. 긴 영문 식별자는 필요한 곳에서 줄바꿈하고 제목을 말줄임표로 숨기지 않는다.

## 3. 정보 구조와 핵심 화면

### 학습 화면

넓은 화면은 `목차 | 본문 | 용어 사전` 구조다. 상단에는 이름과 과정 이동, 화면 도구만 둔다. 본문 위에는 `단원명 / 강의 제목`, 1~2문장 학습 목적, 현재 언어 기준을 배치한다. 학습 목표·선수·공식 출처의 추가 정보는 자세히 펼칠 수 있지만 핵심 설명은 기본 노출한다.

```text
JavaScript-edu                              과정 목차   학습 안내
────────────────────────────────────────────────────────────────
과정 목차             02 함수와 상태                     용어 사전
단원별 강의           클로저와 상태                      [검색어     ]
  강의                짧은 학습 목적                     이번 수업의 용어
  현재 강의           ─────────────────────              클로저 / closure
                      이론 예시 문제풀이 실무 심화 직접 코딩  간단 설명
                      소제목·설명·코드·상태 추적          자세히 보기
                      다음 절                           렉시컬 환경 …
```

위 그림은 구조 설명이고 실제 합성 화면은 아니다. 시안의 대표 수업은 기존 ID `bindings-and-closures`를 사용한다. 요청된 7개 핵심 주제의 목차를 시안용 탐색 샘플로 노출할 수 있지만, 그것이 전체 제품 과정이나 구현 수업 수를 뜻하지 않도록 `화면 시안 · 일부 주제`라고 밝힌다. 전체 과정은 공통 32강·브라우저 8강·Node.js 8강·통합 4강 계획을 유지한다.

### 과정 목차

단원별 제목과 강의명을 평문 목록으로 제공한다. 전체 강의 검색과 용어 검색은 다른 입력으로 구분한다. 과정 화면은 카드 모음보다 단원·선수·도착 목표를 읽기 쉬운 목록으로 구성한다. “수업 준비 중” 항목을 눌러 빈 본문으로 보내지 않고 상태와 현재 제공 범위를 알려준다.

### 5단계 학습

`이론 → 예시 → 문제풀이 → 실무 심화 → 직접 코딩`을 같은 위치에서 유지한다. 화면에서는 번호를 작게, 이름을 분명하게 표시한다. 현재 단계는 밑줄+글자 굵기+프로그램 상태로 식별한다. 색만으로 구분하지 않는다.

단계가 같은 페이지의 패널을 바꾸는 시안에서는 tablist/tab/tabpanel 관계를 제공한다. Tab은 선택된 탭 한 곳으로 진입하고 좌우 방향키·Home/End로 탭 사이를 이동한다. Enter/Space로 선택을 확정하며 선택 뒤 본문 첫 줄로 강제 이동하지 않는다. 줄바꿈된 탭도 같은 논리적 순서를 유지한다.

단계는 자유롭게 이동할 수 있다. 제품에서는 이동 전에 코드·메모 저장을 시도하고 실패하면 입력을 메모리에 보존해 재시도 경로를 준다. 저장 실패를 숨기면서 성공으로 안내하지 않는다. 자동 채점·실행 준비·읽기·설계 기록은 각각 다른 상태다.

시안의 단계 전환은 실제 콘텐츠를 바꾸되, 편집/채점을 제공하지 않는 단계에는 “화면 구성 예시이며 실행·제출은 연결되지 않았습니다”를 표시한다. 보기용 코드와 예상 결과를 실제 실행 결과로 부르지 않는다. 목차와 단계를 눌러도 완료 수나 성적은 증가하지 않는다.

## 4. 용어 사전 기능

### 기본 구조

1. 넓은 화면 오른쪽에 검색 입력과 현재 수업 관련 용어 5~8개를 표시한다.
2. 검색하면 전체 사전에서 용어를 찾고 표제어·영문·간단 설명을 보여준다.
3. 각 항목의 `자세히 보기`를 누르면 상세 설명을 연다.
4. 상세를 닫으면 검색 결과와 읽던 본문 위치로 돌아온다.

한 항목은 표제어, 영문 병기, 1~2문장의 요약, 자세히 보기로 구성한다. 요약을 가로채는 툴팁이나 강제 hover는 사용하지 않는다. 검색 결과가 많으면 사전 영역 안에서 스크롤하며 본문을 밀어내지 않는다. 요약을 정해진 높이에 잘라 맞추지 않는다.

### 검색 계약

| 항목 | 결정 |
| --- | --- |
| 범위 | 검색어가 있으면 전체 사전. 빈 입력이면 현재 수업 관련 항목. 두 상태를 제목으로 구분한다. |
| 검색 키 | 한글/영문 표제어, 검토한 별명, 핵심 키워드 |
| 예 | `클로저`, `closure` → 동일 항목. `환경 레코드`, `Environment Record`, `environmentRecord` → 동일 항목 |
| 정규화 | 앞뒤 공백·연속 공백·영문 대소문자 차이를 허용한다. 코드 기호를 모두 삭제하지 않고 필요한 표기를 별명으로 관리한다. |
| 순위 | 표제어·별명 완전 일치 → 앞부분 일치 → 포함 일치. 같은 순위는 한글 표제어 기준 안정 정렬 |
| 한글 입력 | 조합 중 기존 결과를 유지하고 Enter 제출·검색 발표를 보류한다. 조합 중 Escape를 사전 닫기로 가로채지 않는다. 조합 종료 후 결과를 갱신한다. |
| 초성 검색 | 이번 시안/첫 기능 범위에서는 제외. `ㅋㄹㅈ` 지원을 암시하지 않는다. 별도 요구 시 초성 판정·동음 결과·IME 검사를 추가한다. |
| 입력 확정 | 조합 종료 또는 일반 입력 후 갱신. Enter를 눌러야만 결과가 나타나는 방식은 쓰지 않는다. |
| 결과 접근 | 검색 input + 일반 결과 목록 + 버튼 구조. 복잡한 combobox 역할을 붙이지 않는다. Tab으로 항목 이동 가능 |
| 결과 안내 | 비조합 입력이 안정된 뒤 `N개 용어`를 `aria-live=polite`로 한 번 발표. 매 글자 전체 목록을 읽지 않음 |
| 검색 초기화 | 이름이 있는 `검색어 지우기` 버튼. 검색 input으로 포커스 복귀 |
| 기록 | 입력한 검색어·검색 이력을 외부에 전송하지 않는다. 시안은 계정·분석 수집을 요구하지 않는다. |

### 검색·오류 상태 문구

| 상태 | 화면 행동/문구 |
| --- | --- |
| 빈 검색 | `이번 수업의 용어`와 추천 항목. `한글 또는 영문으로 검색` 힌트 |
| 공백만 입력 | 빈 검색과 동일하게 처리 |
| 결과 있음 | `전체 사전 · 3개 결과`, 표제어·영문·요약·자세히 보기 |
| 결과 없음 | `‘검색어’에 해당하는 용어가 없습니다.`와 `다른 이름이나 영문으로 검색해 보세요.` + 지우기 버튼 |
| 로딩 실패 | `용어 사전을 불러오지 못했습니다.` + 다시 시도. 본문과 목차는 계속 사용 가능 |
| 상세 ID가 없음 | `이 용어는 현재 개정에 없습니다.` + 사전으로 돌아가기. 깨진 ID를 임의의 다른 용어로 대체하지 않음 |
| 설명/출처 누락 | 빈 항목을 공개하지 않고 작성 검수에서 차단. 시안 샘플 미수록이면 `시안에 포함되지 않은 항목`으로 구분 |

정적인 로컬 데이터로 제공하는 시안에는 실제 네트워크 로딩을 흉내 내는 spinner를 넣지 않는다. 로딩 실패 상태는 제품 연동 시 필요한 설계다.

### 상세 설명

순서: 표제어·영문 → 짧은 정의 → 코드 또는 구체적 사례 → 혼동하기 쉬운 점 → 관련 용어 → 연결 강의·공식 출처. 길이는 하나의 질문을 해소하는 데 필요한 정도로 제한하며 교재 한 장을 그대로 복사하지 않는다.

예를 들어 클로저 상세는 “함수가 생성될 때의 렉시컬 환경과 함께 동작하여 바깥 바인딩을 참조하는 것”을 설명하고, 두 카운터의 상태가 독립적인 작은 코드를 제공한다. “값을 영구 복사해 저장한다” 또는 “함수 호출이 끝나면 모든 지역 변수가 즉시 삭제된다” 같은 설명을 피한다. 이 예시는 설명 방향이며, 실제 용어 원고는 교육 내용 검토를 별도로 통과해야 한다.

본문의 주요 용어에는 선택적으로 용어 링크를 둔다. 첫 등장과 혼동이 예상되는 곳에 제한하고 모든 반복 단어를 링크로 만들지 않는다. 점선/밑줄과 명확한 접근 가능한 이름으로 식별하며 마우스 hover 없이도 작동한다. 링크를 열어도 본문의 선택한 텍스트·스크롤·수업 단계는 보존한다.

## 5. 팝업·시트·포커스 계약

넓은 화면의 사전은 비모달 보조 영역이다. 검색 결과의 자세히 보기는 중앙 상세 팝업으로 연다. 좁은 화면은 사전 버튼으로 여는 모달 drawer/sheet를 사용하며 검색과 상세를 그 안에서 전환한다. 상세를 위해 모달을 한 겹 더 쌓지 않는다.

| 상황 | 동작 |
| --- | --- |
| 데스크톱 상세 열기 | 상세 제목으로 포커스 이동. 본문/목차/사전은 상호작용 불가 |
| 좁은 화면 검색 열기 | 검색 input으로 포커스 이동. 소프트 키보드가 열린 상태에서도 입력·닫기 접근 가능 |
| 좁은 화면 상세 열기 | 같은 모달 안의 상세 화면으로 전환. 검색어와 결과 위치를 보존하고 제목으로 포커스 이동 |
| 상세의 뒤로 버튼 | `검색 결과로`를 표시. 검색어·결과 스크롤·해당 항목 포커스 복원 |
| Escape | 데스크톱 상세 닫기. 좁은 화면은 상세→검색, 검색→닫기. 한 번의 입력으로 여러 층을 함께 닫지 않음 |
| Tab/Shift+Tab | 활성 모달 내부에서 순환. 배경 요소로 이동하지 않음 |
| 닫기 | 보이는 닫기 버튼 제공. 원래 열기 버튼으로 복귀; 버튼이 사라졌으면 같은 용도의 사전 버튼으로 복귀 |
| 배경 클릭 | 상세/사전 읽기 상태는 닫기 허용. 본문 입력을 지우거나 단계 이동하지 않음 |
| 배경 스크롤 | 열린 동안 잠그고 닫은 뒤 원 위치 복원. 가로 스크롤바 변화로 본문이 옆으로 튀지 않게 처리 |
| 상세 스크롤 | 내용만 세로 스크롤. 제목·닫기/검색 결과로 접근을 유지하고 포커스가 가려지지 않게 함 |
| 관련 강의 이동 | 상세를 닫고 해당 강의/절로 이동하는 명시적 행동. 제품에서는 미저장 입력 보호 후 수행 |
| 외부 출처 | 새 탭 여부를 표시하고 기존 수업은 유지. 내부 이동처럼 보이게 꾸미지 않음 |

W3C의 [모달 대화상자 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)에 따라 이름, 내부 포커스, Escape, 복귀 위치를 구현한다. 긴 구조적 설명은 팝업 전체를 하나의 `aria-describedby`로 연결해 한꺼번에 읽게 하지 않는다. `aria-modal` 속성만 붙이는 것은 동작 구현의 대체가 아니다.

## 6. URL·재개·읽기 맥락

제품의 수업·단계·선택 용어는 재현 가능한 탐색 상태를 가진다. 시안에서도 지원하는 수업/단계/용어는 새로고침과 뒤로/앞으로로 복원한다. 예시 상태는 `lesson=bindings-and-closures`, `step=theory`, `term=closure`다. 구체적인 query/hash 형식은 시안 구현 안내에 기록한다.

- 검색 입력 한 글자마다 URL과 history를 추가하지 않는다. 용어 ID만 공유 가능한 주소에 담고 사용자의 자유 검색어는 주소에 저장하지 않는다.
- 용어 상세를 열 때 수업과 단계 값을 보존한다. 뒤로 가기는 먼저 상세를 닫거나 직전 용어로 돌아가며, 본문이 최상단으로 뛰지 않는다.
- 상세 deep link로 처음 진입한 뒤 닫으면 같은 수업 주소로 돌아간다. 불필요하게 외부 이전 페이지로 이탈하지 않는다.
- 새로고침 복원과 화면 크기 변경 중에도 사전 검색·상세 상태가 서로 충돌하지 않게 한다. 표시 방식만 바꾸고 동일한 콘텐츠와 의미 상태를 유지한다.
- 제품의 초안·메모·성취에는 `lessonId`와 `contentRevision`을 포함한다. 시안에서 영구 저장이나 기기간 동기화가 없으면 있다고 표시하지 않는다.

## 7. 반응형과 입력 규칙

breakpoint는 화면 이름보다 읽기 폭을 보장하기 위한 기준이다. 큰 글자로 인해 내용이 맞지 않으면 같은 접힘 규칙을 적용한다. 3열을 강제로 유지하지 않는다.

| 조건 | 레이아웃과 행동 |
| --- | --- |
| 1280 CSS px 이상 | 목차 208px + 본문 가변(최대 720px) + 사전 260px. 열 사이 24~32px, 바깥 24~32px. 전체 약 1440px 안에서 중앙 정렬 |
| 768~1279px | 목차 180~200px + 본문. 사전은 상단 `용어 사전` 버튼으로 접근하고 우측 340~400px drawer로 열림 |
| 320~767px | 본문 1열, 바깥 12~16px. 상단 목차/사전 버튼. 목차와 사전은 각각 full sheet, 동시에 열지 않음 |
| 320px | 실제 본문 폭 288px 이상 목표. 입력 100%, 긴 영문 줄바꿈, 버튼 라벨 2줄 허용. 모든 본문을 가로 스크롤하게 만들지 않음 |
| 5단계가 한 줄에 안 맞음 | 2~3개씩 줄바꿈하여 모든 단계 이름 노출. 문서 밖으로 넘치는 탭 목록을 기본값으로 쓰지 않음 |
| 높이 500px 이하·모바일 가로 | 상주 상단 영역을 최소화하거나 sticky 해제. 닫기·검색·선택 결과가 화면을 독점하지 않음 |
| 글자 200% | 고정 높이 해제·레이블 줄바꿈·단일열 전환. 팝업은 화면 안에서 세로 스크롤하며 닫기 접근 유지 |
| 표·긴 코드 | 해당 영역 내부 가로 스크롤 + 접근 가능한 이름. 본문 전체 가로 overflow 없음. 가능한 짧은 예제를 우선 편집 |
| 방향/너비 전환 | 현재 단계·용어·검색·본문 위치 보존. 모달 모드 전환 뒤 포커스가 숨겨진 요소에 남지 않음 |

상주 버튼과 결과의 자세히 보기 버튼은 이 제품의 설계 목표로 44×44 CSS px 이상의 입력 영역을 확보한다. 본문 안 링크는 문장 흐름을 유지한다. WCAG 2.2 AA의 최소 기준은 예외를 포함한 24×24 CSS px이며, 이 문서의 44px 목표와 구분한다. [W3C 입력 목표 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

키보드 기본 경로는 `본문 바로가기 → 목차 → 학습 단계 → 본문 행동 → 사전`이다. `용어 사전으로 이동` 바로가기 또는 상단 도구로 긴 본문을 건너뛸 수 있어야 한다. 숨긴 패널은 Tab 경로에서도 제외한다. 텍스트 선택·복사·터치 스크롤·브라우저 기본 확대를 막지 않는다. 단축키는 없어도 모든 기능을 사용할 수 있어야 하며 `/` 같은 문자 키를 페이지 전역에서 임의로 가로채지 않는다.

320 CSS px reflow와 200% 글자 확대는 서로 다른 검사다. 각각 [W3C reflow 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)과 [글자 확대 설명](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)을 기준으로 확인한다. 작은 viewport 에뮬레이션만으로 실제 브라우저 200% 확대나 실제 모바일 검사까지 통과했다고 쓰지 않는다.

## 8. 용어 데이터와 편집 소유권

용어는 화면 문구에 하드코딩한 설명과 별도로 관리한다. 교육 작성자가 정의·예제·출처를 작성하고, UI 담당자는 검색·표시·상태를 책임진다. 설명 개정과 UI 배포 버전은 구분한다.

| 필드 | 의미 |
| --- | --- |
| `id` | URL·관련 용어에서 사용하는 안정 식별자 |
| `labelKo`, `labelEn`, `aliases` | 한글/영문 표제어와 검색 별명 |
| `summary` | 검색 결과에서 완결되는 1~2문장 설명 |
| `definition`, `example`, `misconceptions` | 상세 정의·작은 사례·혼동 방지 |
| `lessonIds`, `relatedTermIds` | 관련 강의·용어의 실제 존재 ID |
| `scope` | ECMAScript / 브라우저 / Node.js / 교육용 개념 등 적용 범위 |
| `sourceRefs`, `reviewedOn`, `contentRevision` | 근거·검토일·개정 |

첫 제품 범위는 요청한 7개 주제를 빠짐없이 찾을 수 있도록 아래 용어군을 포함한다. 이 목록은 검색·정의 편집 대상이며 새 강의 수를 뜻하지 않는다.

| 주제 | 필수 용어군 |
| --- | --- |
| 데이터 타입 | 원시값, 객체, 식별자, 변수, 바인딩, 선언, 할당, 재할당, 불변성, 변경, 참조, 얕은 복사, 깊은 복사, `undefined`, `null` |
| 실행 컨텍스트 | 실행 컨텍스트, 호출 스택, `VariableEnvironment`, `LexicalEnvironment`, 환경 레코드, 호이스팅, TDZ, 렉시컬 스코프, 스코프 체인, 외부 환경 참조 |
| `this` | `this`, 호출 방식, 메서드, `call`, `apply`, `bind`, 화살표 함수, `thisArg`, strict mode, Script/Module |
| 콜백 | 콜백, 고차 함수, 제어권, 동기/비동기, 콜백 지옥, Promise, `async`/`await` |
| 클로저 | 클로저, 도달 가능성, 가비지 컬렉션, 정보 은닉, 부분 적용, 커링 |
| 프로토타입 | 생성자 함수, `prototype`, `[[Prototype]]`, 인스턴스, `constructor`, 프로토타입 체인, 프로퍼티 가림, 메서드 재정의 |
| 클래스 | 클래스, 인스턴스 필드, static, private, 상속, `extends`, `super`, 합성 |

과거 교재 표현은 검색 별명으로 찾을 수 있게 하되 최신 명세의 개념과 연결한다. 예컨대 `outerEnvironmentReference`를 검색할 수 있어도 이를 모든 현대 실행 컨텍스트가 동일한 모양으로 저장하는 엔진의 실제 메모리 필드라고 설명하지 않는다. 같은 철자 `constructor`의 용도가 다르면 표제어 보조 설명에서 구분한다. 출처·호스트 경계와 메모리/GC 관련 단정은 교육 검토 담당자가 확인한다.

시안에는 대표 용어만 포함해도 된다. 실제 수록 개수를 README와 화면 범위 안내에서 명시하고 전체 사전 완성으로 표현하지 않는다. 검색 결과의 기술 내용 정확성은 상호작용 검증과 별도 항목이다.

## 9. 이번 작동 시안의 범위

필수 구현은 대표 수업과 5단계 전환, 시안 목차 탐색, 한영/별명 검색, 결과/결과 없음, 간단 설명, 상세 열기·닫기, 키보드·포커스 복원, 화면 크기에 따른 보조 영역 전환이다. 문서에서 명세한 기능과 시안에서 실제 제공한 기능의 차이는 README에 기록한다.

제품의 학습 DB·과제 파일·runner와 연결하지 않는다. 실제 실행·제출·채점·기기간 저장을 대신하는 성공 애니메이션이나 허위 진도를 만들지 않는다. 읽기용 코드의 복사를 제공하면 성공/실패를 실제 클립보드 결과로 표시한다. 구현하지 않은 버튼은 목적과 준비 상태를 알 수 있도록 정리하며 눌러도 반응 없는 장식 버튼을 남기지 않는다.

후속 제품 구현 순서는 `용어 데이터 검수 → 대표 수업의 읽기/사전 흐름 → 편집·저장 → 실제 실행·제출 → 성취 연결 → 전체 과정 확대`다. 이번 시안의 화면 코드가 최종 제품 기술 선정이나 실행기 채택을 확정하지 않는다.

실제 모바일 장치, 실제 한국어 IME, 스크린리더, 브라우저 조합을 수행하지 못하면 각각 미검증으로 기록한다. 에뮬레이션·DOM 상태 확인·합성 화면·실제 기기는 별도 근거다. 자동 접근성 검사가 통과해도 전체 WCAG 적합성이나 사용자 연구 결과로 일반화하지 않는다.

설계 문서 작성자의 자체 판정: **PASS — 사용자 과업·화면·상태·반응형·수용 기준을 명세함.** 사용자 시각 선호 승인과 실제 기능·화면 최종 판정은 아직 이 문서의 주장 범위에 없다. 실제 구현 검증·독립 리뷰·시각 판정은 [검증 기록](verification.md)에 수행 근거와 함께 남긴다.

# 구현 마일스톤

2026-10-15 사용자가 실제 실행·자동 채점과 확정 로드맵의 순차 구현, 마일스톤별 커밋·푸시를 승인했다. 승인한 피스타치오 UI를 유지한다. 패키징은 모든 기능·교재의 검증 뒤 마지막 한 번으로 미루며 현재 실행하지 않는다. 기존 CONTRIBUTING.md의 유형/작업 브랜치와 Conventional Commits를 적용한다. 원격 main은 강제로 바꾸지 않으며 작업 브랜치에 검증한 단계별 커밋을 푸시한다. PR 병합·호스팅·설치 패키지 게시 승인은 이 작업과 구분한다.

| 마일스톤 | 구현 범위 | 종료 조건 |
| --- | --- | --- |
| 승인 기준선 | 확정 기획·로드맵·피스타치오 제품 UI와 용어집 | 기존 검증 소스/리뷰 대조, 관련 파일만 커밋·푸시 |
| M1 | 기존07 클로저의 실제 실행·제출 검사·취소·결과/저장 연결 | 정답 통과·미완성/대표 오답 실패·무한반복 timeout·취소·위조/낡은 결과 거부·수정 후 PASS 무효화·실제 브라우저 확인 |
| M2 | 공통01–11, 순서 목차·문제·진도 | 각 수업5단계/공식출처/정오답·경계 fixture·실제 실행/개정별 상태 검증 |

| M4 | B01–B08·C01–C04 브라우저 경로 | 실제 DOM/이벤트·HTTP/저장·접근성/반응형 및 통합 인수 검사 |
| M5 | 고정 Node 제공자·N01–N08·Node 통합 경로 | 실제 Node 버전·권한/네트워크 한계·파일/프로세스 정리·정오답·경계 fixture |
| 최종 | 전체 인수 확인 뒤 단 한 번 패키징 | junbo-desktop-runtime-packaging의 공급자 전체 배포본/고지/최종 설치본 무결성·네이티브 검증 |

각 단계는 독립 코드 검토와 관련 기능 검사를 거친다. UI 변경은 실제 합성 화면으로 검수한다. 실제 실행하지 않은 과제는 executionVerified:false를 유지한다. 초안·실행·코딩 통과·퀴즈·메모 자가확인을 분리하며 저장이나 예상 출력을 통과로 표시하지 않는다. 공개 브라우저 검사는 자가 학습 검증으로, 비밀 검사·위변조 방지 성적 인증이 아니다.

브라우저는 hard heap quota를 제공하지 않는다. Worker를 악성 제출용 완전한 OS 격리라고 표시하지 않는다. M1은 전용 실행 응답의 제한 CSP·시간/출력 제한·실행별 새 Worker와 private MessagePort를 사용하고 비교는 부모에서 수행한다. Node 24.22.0 후보의 Permission Model도 보안 샌드박스나 네트워크 차단이라고 표시하지 않는다. 실제 제공자 검증 후 가용성을 갱신한다.

로컬 artifacts/는 과거 UI 진단용 캡처·환경별 실행 도구로 보존하며 Git 게시 대상에서 제외한다. 검증 기록의 원본/현재 소스 해시를 구분한다. 커밋 전 새 원격 상태와 staged diff를 확인하고 비밀정보·개인 경로·무관한 변경을 포함하지 않는다.
